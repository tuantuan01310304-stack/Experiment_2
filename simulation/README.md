Simulation ? mechArm270 Fixed-Point Grasping

This directory contains the ROS 2 and Gazebo / Ignition implementation of the fixed-point pick-and-place experiment for the mechArm270 robotic arm.

The simulation is used to validate the complete grasping workflow before physical-robot execution.

1. Simulation task

The experiment is a fixed-point object transfer task.

The robot starts from the home configuration and performs:

Home
  ?
Above Point A
  ?
Descend to grasp
  ?
Close gripper
  ?
Lift object
  ?
Move above Point B
  ?
Descend to placement height
  ?
Open gripper
  ?
Lift
  ?
Return Home

The task can be repeated for multiple cycles to evaluate the stability of the grasping procedure.

2. Two task implementations

Two implementations are preserved in the simulation package.

2.1 Initial version

Files:

code/lws_transfer_task.py
code/lws_transfer.launch.py
config/lws_transfer_params.yaml

The initial version is the first complete implementation of the fixed-point transfer task.

It contains the original task planning, robot motion control, gripper control, simulation checking, and execution logging developed during the experiment.

This version is retained as a development/reference version and is not replaced by the final implementation.

2.2 Final version

Files:

code/final_grasp_task.py
code/final_grasp.launch.py
config/final_grasp_params.yaml

The final version is the finalized simulation implementation.

Its main purpose is the same as the initial version, but the program is reorganized into clearer functional modules. The main components separate:

Robot kinematic calculation
Target solving
ROS 2 motion control
Simulation-object management
High-level grasping and transfer execution

This structure makes the final task node easier to read, maintain, test, and extend.

3. Configuration

The two versions use separate parameter files so that their configurations do not interfere with each other.

Initial version
lws_transfer_params.yaml

Contains the original task parameters, including:

Robot base pose
Point A / Point B
Safe height
Tool-tip offset
Gripper opening and closing positions
Arm and gripper motion duration
Repetition count
Gazebo world name
Simulation checking options
Final version
final_grasp_params.yaml

Contains the corresponding parameters for the final task implementation.

The physical experimental setup remains the same, so the robot model, world, controller configuration, and basic task geometry are shared.

ros2 launch mecharm_grasp_lws lws_transfer.launch.py
Final version
ros2 launch mecharm_grasp_lws final_grasp.launch.py

5. ROS 2 package

The simulation uses an ament_python ROS 2 package:

mecharm_grasp_lws

The package provides separate executable entries for the two task implementations.

Conceptually:

mecharm_grasp_lws
??? lws_transfer_task

The package dependencies include the ROS 2 control/action interfaces, sensor messages, robot state publishing, Xacro, controller management, Gazebo?ROS bridging, and the mechArm description package.

6. Simulation environment

The experiment uses a Gazebo / Ignition world containing:

The mechArm270 robot
A table/work surface
A target object
Fixed grasping and placement regions

The robot base position and target points are defined through the parameter files.

The final configuration uses the same physical task geometry as the validated experiment so that the software restructuring does not change the experimental objective.

These files are used to support task verification and the final experiment report.

9. Recommended testing procedure

Before testing either version, rebuild and source the ROS 2 workspace:

cd ~/colcon_ws
colcon build --packages-select mecharm_grasp_lws
source install/setup.bash

Then launch one version at a time.

Test the initial version
source ~/colcon_ws/install/setup.bash
ros2 launch mecharm_grasp_lws lws_transfer.launch.py
Test the final version
source ~/colcon_ws/install/setup.bash
ros2 launch mecharm_grasp_lws final_grasp.launch.py

Only one task implementation should be run at a time to avoid two independent task nodes commanding the same robot.
